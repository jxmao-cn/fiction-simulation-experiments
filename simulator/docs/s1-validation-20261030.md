- 新增 `integrator_report_check.cpp`：静态二次势、静态步长无关性、动态离散参考、maxIter=0 与非有限梯度失败检查。

- CMake 给原 simulator smoke 加上 FAIL 输出匹配，避免仅靠旧的固定零退出码判断成功。未改原 simulator 主程序。

静态/诊断为 C++ API 扩展；Python 原参考没有相应静态与 StepReport 入口，本轮未扩写 Python。正常动态路径仍需靠回归检查保证；失败语义与迭代上限处理确有行为变化，不能描述为完全没有算法影响。新增 State 成员也可能影响外部对 State 的双元素结构化绑定，仓库内当前调用已编译检查。

## 4. 离线诊断：已知机制与待验证原因

**已知代码机制**：只有搜索方向率不大于 tol 且 DBC 未全部满足时，旧循环才倍增罚刚度；倍增后重算能量，但保留旧搜索方向，下一次更新后才重新求方向。本轮保留此机制，没有为通过 S1 静默改变它。

**假说 A**：刚度变更后沿旧方向线搜索，方向与新目标不一致，可能引起大量回溯。**假说 B**：极小更新在浮点精度下可能不改变坐标，而“不增能”比较仍接受同值，导致停滞。最终方向率略高于阈值也可能阻止继续倍增罚刚度。

当前只有每载荷汇总，没有逐迭代刚度、alpha、位移增量和能量差，不能确认上述假说，也不能把最后一轮数值外推到前面每轮。没有证据将其归因为 NH 公式错误或机器算力不足。

建议下一步先增加逐迭代诊断，再设计仅改变“倍增后立即重算方向”的受控对照，评估对旧动态路径的影响；这属于后续修订和诊断实验，本轮未执行。不以增加迭代上限或放宽误差标准掩盖失败。
